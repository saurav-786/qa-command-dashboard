Owner: Soumya Saurav Pattnaik. Every headless run reads this file first (scripts/run-prompt.md step 0) and appends a dated lesson at the end (step 8) whenever:
- a person reports something QA missed (e.g. Jonas's screenshot after a READY/NOT READY verdict),
- a check produced a false alarm and had to be corrected,
- a bot or tool behaved in a new way (rename, new wording, new capability),
- a Wrike/Shopify/API limit was hit.
Format: `- YYYY-MM-DD · <task id> · <what happened> → <rule for next time>`. Keep each lesson to 1–3 lines; never delete old ones (mark "superseded by …" instead).

QA NOT READY rounds this week came from: non-DE markets (German text on ES/FR/IT/NL, wrong prices after variant change in AT/CH/ES/NL), mobile layout (long words, uneven cards), interaction bugs (add-to-cart added 7 unselected items; first tap pauses video), preview behind live (would undo released fixes), and content in other languages still describing the old spec.
- → In every report, list each Shopify Bot claim as confirmed / not confirmed / wrong, and always test what it did NOT check (other markets, 360 px, rotation, real flows, preview-vs-live drift).
- 2026-09-28 · 4574392050 · Defect tasks are now created automatically (`wrike.py defect`): registry + keyword search against existing tasks; a broad keyword ("sort") matched an unrelated WoodPad task → always `--dry` first and use precise keyword groups.
- 2026-09-28 · 4574392050 · The evidence script was never written because the command exited on "BUSY" before the heredoc; the queued job then failed. → Write scripts to disk first, then check the lock; never put the file creation after an early exit. - 2026-09-28 · botwatch · Release wording varies: "PR #87 is live", "PR #89 is live", "✅ Applied · live now" (store data) were NOT matched → 2 code releases + 2 data changes got no post-release run. → LIVE_DONE_RE now covers them; lib/botwatch.py alerts on any release-like bot comment the regex misses (runs hourly + before each run).

The bot's plan did not warn about it. → On every gallery/media data change, check custom.pdp_gallery_notes (and any metaobject that references media) against the new image list, and compare the captions per slide across colours.
- 2026-09-28 · 4574047230 · After a variant tap, AT/CH/ES/FR/IT/NL PDPs showed DE prices (CH in €), because a client script rewrote localization=CH → DE in the test browser (the test machine is not in those markets). → Before calling a post-switch price a DEFECT, check the localization cookie before and after load.
