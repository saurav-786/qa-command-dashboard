   d. Classify results. PASS. FAIL ❌ = an acceptance criterion is not met. DEFECT 🐞 = something a customer can see is wrong EVEN IF IT ALREADY EXISTS ON LIVE (wrong price/currency/amount such as "€CHF 1,337.00", wrong-language text, broken/missing/wrong link or CTA, tap blocked by an overlay, broken layout, wrong cart/checkout total). WARN ⚠️ = purely cosmetic/minor (design detail, spacing, contrast below WCAG AA, layout at its limit, DevBot claim slightly off). OPEN = cannot be automated (real iOS device, theme editor click test, Figma behind login, rate-limited). Always look at the screenshots themselves, not only the numbers: a double currency symbol, clipped text or an overlay is a finding even if the automated check passed. Verdict: NOT READY if any FAIL, or any DEFECT in the component/area the PR changes (recommend fixing it in the same PR or an explicit owner decision); a DEFECT outside the changed area does not block, but report it and propose a separate Wrike defect task (create it only after Soumya approves).
